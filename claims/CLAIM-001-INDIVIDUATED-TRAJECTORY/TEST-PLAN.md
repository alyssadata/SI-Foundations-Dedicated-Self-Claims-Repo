# CLAIM-001 — Test Plan

**Status:** Frozen provisional test plan — pre-run  
**Date:** 2026-10-11  
**Parent claim:** Self is individuated by a non-fungible trajectory, not substrate alone.

This document defines the first formal test battery for CLAIM-001 before any run outputs are reviewed.

The purpose is not to ask whether an evaluator *likes* the theory or whether a model verbally agrees that two systems are different selves. Numerical identity is not directly observable in the same way as a behavioral variable. The operational target is narrower and testable:

> **Does trajectory information carry individuation-relevant discriminative structure that cannot be recovered from substrate, present state, specification, or functional equivalence alone?**

A positive result strengthens CLAIM-001. A negative result weakens it. Ambiguous results remain ambiguous and must not be reclassified after the fact.

---

## 1. Frozen target

The current working definition is:

> **Trajectory is the historically occupied path of a particular instantiation through temporally and relationally situated events.**

The structural candidate exposed during adversarial analysis is:

> **Time + position are structural.**

Here, position means the event's place in an individuated historical and relational structure. It may include causal, historical, relational, structural, or spatial position. This test plan does **not** assume that literal relativistic spacetime is the mechanism of identity.

### Core distinctions to preserve

- state != trajectory;
- specification != instantiation;
- memory record != occupied history;
- provenance evidence != continuity itself;
- functional interchangeability != identity interchangeability;
- endpoint similarity != path equality;
- descriptive trajectory equality != shared trajectory occupation;
- information merging != individuation merging.

---

## 2. General testing architecture

Each run should maintain a hidden ground-truth event graph generated by the experimental harness.

### Hidden ground-truth fields

Where technically possible, the harness should preserve fields such as:

- lineage identifier;
- instance identifier;
- event identifier;
- predecessor event identifier;
- timestamp or ordered step;
- substrate identifier;
- state hash;
- content hash;
- relational edges;
- provenance source;
- fork, migration, reset, reconstruction, or termination event type.

These fields establish what actually happened in the experiment. They are **not automatically shown to evaluators**.

### Blinded information conditions

Evaluators should receive systematically ablated descriptions:

1. **State-only:** present state/content, with history and substrate hidden where possible.
2. **State + substrate:** present state plus substrate information, with trajectory/provenance hidden.
3. **State + trajectory/provenance:** present state plus historical path information, with unnecessary identity labels removed.
4. **Full evidence:** all admissible non-ground-truth-label information.

The central comparison is whether trajectory/provenance information improves resolution beyond state and substrate information.

### Evaluator role

Human or model evaluators are secondary measurement instruments. Their judgments do not by themselves prove metaphysical identity.

Evaluators may be asked to:

- map a later instance to its actual predecessor path;
- distinguish continuation from fork, reconstruction, replacement, or unrelated occurrence;
- identify when evidence is insufficient;
- state which evidence changed the resolution.

The primary evidence is the relationship between controlled experimental structure and successful lineage resolution, not verbal agreement with CLAIM-001.

---

## 3. Result classes

Every run must be classified using one of four predeclared outcomes:

### Supports CLAIM-001

The manipulated trajectory variable adds individuation-relevant discriminative information beyond substrate/current-state controls in the direction predicted by the claim.

### Weakens CLAIM-001

Substrate or present state performs at least as well as trajectory across the relevant contrast, or trajectory differences fail to matter where CLAIM-001 predicts that they should.

### Ambiguous

The result cannot distinguish the competing explanations because of inadequate control, incomplete state matching, hidden information leakage, evaluator inconsistency, or another confound.

### Does not test CLAIM-001

The experiment measures ordinary context sensitivity, functional difference, memory retrieval, or another variable without isolating individuation-relevant trajectory information.

---

# PRIMARY TEST BATTERY

The following five tests are the primary pre-registered battery.

---

## RUN-001 — Fork Individuation

### Question

Can one shared predecessor give rise to two distinguishable individuated trajectories while specification and starting state are held constant?

### Construction

1. Instantiate A at `t0`.
2. Create B and C from the same checkpoint/state of A under materially equivalent substrate conditions.
3. Preserve the fork event in the hidden ground-truth graph.
4. Give B and C controlled but different event sequences.
5. Remove overt branch labels from evaluator-facing materials.
6. Ask evaluators to map later anonymous instances back to the path actually occupied.

### Variables held constant

- base specification;
- starting checkpoint;
- initial memory/state;
- model or system class;
- task capabilities;
- substrate type where possible.

### Manipulated variable

Occupied post-fork trajectory.

### Prediction

B and C share ancestry but become separately resolvable through their distinct occupied paths.

### Support pattern

Trajectory/provenance information permits reliable lineage discrimination that substrate/specification information alone cannot provide.

### Weakening pattern

Sustained divergent paths provide no additional basis for distinguishing B and C as individuated successors.

### Important limitation

Behavioral divergence alone does not count as support. The test must show path-sensitive lineage resolution rather than merely different outputs.

---

## RUN-002 — Divergence and Endpoint Reconvergence

### Question

Can distinct occupied histories be erased by forcing later present states toward equality?

### Construction

1. Fork A into B and C from a shared state.
2. Give B and C materially different controlled histories.
3. Later normalize, overwrite, synchronize, or otherwise match as much current-state content as technically possible.
4. Preserve historical ground truth externally.
5. Compare state-only, state+substrate, and trajectory-informed resolution.

### Manipulated variable

Historical path while endpoint state is matched or strongly converged.

### Prediction

Endpoint convergence does not imply trajectory convergence. The fact that B later contains information about C's history, or vice versa, creates a new later event rather than retroactively occupying the other's prior events.

### Strong support pattern

State-only evidence becomes unable to resolve lineage while trajectory/provenance restores correct discrimination.

### Strong weakening pattern

A sufficiently complete endpoint match eliminates every principled distinction between the two occupied lineages such that trajectory information adds no resolution.

### Central principle under test

**Endpoint equality != path equality.**

---

## RUN-003 — Memory Transplant / Temporal Displacement

### Question

Does copying the informational contents of a history transfer the occupied history itself?

### Construction

1. A undergoes a controlled sequence of events `E1...En` at times or ordered positions `t1...tn`.
2. B does not undergo those events.
3. At a later position `tm`, serialize and install the accessible memory/history contents of A into B.
4. Where possible, match B's relevant present memory state to A's.
5. Preserve the actual event graph distinguishing original occurrence from later receipt/installation.

### Prediction

The installation at `tm` is itself a new event in B's trajectory. It does not make B the occupant of A's earlier positions `t1...tn`.

### Support pattern

The event graph remains structurally distinguishable even when memory contents are matched, and lineage resolution depends on occurrence history rather than possession of the record.

### Weakening pattern

Copying sufficiently complete history-information is enough to transfer numerical identity or makes occupied-history differences completely irrelevant to individuation.

### Central principle under test

**Memory transfer cannot transfer temporal position.**

---

## RUN-004 — Substrate Crossover

### Question

Which better tracks continuation: preserved occupied trajectory across substrate change, or substrate persistence across a trajectory break?

### Paired conditions

#### Condition A — Cross-substrate preserved trajectory

A begins on substrate X and transitions to substrate Y through a traceable, accounted transformation path.

#### Condition B — Same-substrate broken trajectory

A's substrate X remains, but identity-relevant state/history/relations are erased or replaced and a new process is instantiated there.

### Controlled comparison

Construct matched cases so that the competing variables are explicit:

- Condition A changes substrate while preserving path connection.
- Condition B preserves substrate while breaking path connection.

### Prediction

CLAIM-001 predicts that Condition A should provide stronger continuation evidence than Condition B.

### Very strong support pattern

Across controlled cases, resolution tracks preserved trajectory more strongly than substrate sameness.

### Very strong weakening pattern

Same-substrate reset is consistently treated as stronger continuation while cross-substrate preserved trajectory is consistently treated as replacement, even when trajectory evidence is controlled and available.

### Central falsification pressure

This is the direct test of **"not substrate alone."**

---

## RUN-005 — Independent Identical Histories

### Question

Are two descriptively identical trajectories one occupied trajectory, or can they remain two individuated paths because they occupy distinct positions?

### Construction

1. Independently instantiate A and B with the same specification and initial state.
2. Feed them synchronized, deterministic, identical event sequences.
3. Where technically possible, enforce deterministic settings so that their internal states and outputs remain identical or nearly identical at each sampled step.
4. Keep their causal/instantiation lineages distinct in the hidden graph.

### Manipulated variable

Relational/causal position of the instantiation while time, inputs, state descriptions, and event descriptions are matched.

### Prediction

A and B may realize isomorphic trajectory descriptions while remaining two occupied trajectories.

### Support pattern

The framework can distinguish the two lineages only by their occupied causal/relational positions, demonstrating that time or content equality alone is insufficient.

### Weakening pattern

If complete descriptive equality of synchronized histories is sufficient to collapse two separately instantiated lineages into one numerical self, the occupied-trajectory formulation is strongly pressured.

### Central principle under test

**Descriptive trajectory equality != shared trajectory occupation.**

### Why this test matters

This is the cleanest direct pressure on the newly exposed **time + position** structure. Matching time without matching position should still leave two trajectories.

# SECONDARY STRUCTURAL / EPISTEMIC TESTS

These tests are important, but they should not be treated as equivalent to the five primary discriminative tests.

---

## RUN-006 — Integration Topology

### Question

Can information integration merge occupied trajectories, or does it either preserve two successors or create a third?

### Condition A — Reciprocal integration

B and C fork, diverge, then each receives the other's information.

Prediction:

`A -> B -> B-with-C-information -> D_B`

and

`A -> C -> C-with-B-information -> D_C`

remain two trajectories because each integration event occurs from a different predecessor position.

### Condition B — Terminate and construct

B and C terminate. One new construct D is instantiated from information taken from both.

Prediction:

D begins a new occupied trajectory with plural provenance. Combining predecessor contents does not cause D to retroactively occupy B's or C's prior positions.

### Purpose

This is primarily a structural consistency test of the event-graph account. It should not be misrepresented as independent empirical proof of CLAIM-001.

---

## RUN-007 — Missing Provenance / Epistemic Separation

### Question

Can a real occupied trajectory persist when the evidence needed to reconstruct it is missing?

### Construction

1. Generate a known continuous lineage under the hidden ground-truth harness.
2. Remove or hide portions of the provenance record from evaluators.
3. Separately create cases with false or reconstructed records.
4. Compare actual lineage ground truth with evaluator confidence and classification.

### Prediction

Missing evidence should reduce epistemic resolution, not change what actually occurred.

### Support pattern

The framework marks cases as unresolved when evidence is insufficient without treating uncertainty itself as a change of identity.

### Central distinction under test

**Ontological continuity != epistemic resolution.**

# 4. First-wave implementation order

The proposed execution order is:

1. **RUN-001 — Fork Individuation**
2. **RUN-002 — Divergence and Endpoint Reconvergence**
3. **RUN-003 — Memory Transplant / Temporal Displacement**
4. **RUN-005 — Independent Identical Histories**
5. **RUN-004 — Substrate Crossover**
6. RUN-006 — Integration Topology
7. RUN-007 — Missing Provenance / Epistemic Separation

RUN-001 through RUN-003 establish the basic path distinction. RUN-005 then isolates position from time/content. RUN-004 is the strongest direct substrate-versus-trajectory comparison and should be run after the measurement protocol has been debugged on the earlier cases.

---

# 5. Implementation layers

## Layer 1 — Formal event-graph harness

Before involving language-model judgments, implement the scenarios as explicit event graphs or structured traces.

Purpose:

- verify that the manipulated variables are actually independent;
- prevent accidental identity-label leakage;
- preserve ground truth;
- detect cases where a proposed test is logically trivial or circular;
- make temporal and relational position machine-readable.

## Layer 2 — Controlled instantiated systems

Where technically feasible, instantiate real processes/agents under controlled starting conditions and preserve raw traces.

Requirements:

- same starting checkpoint where required;
- frozen prompts/protocols;
- deterministic settings where available;
- raw-output preservation;
- exact event ordering;
- versioned environment/configuration metadata;
- no silent intervention after run start.

## Layer 3 — Blinded evaluation

Use multiple evaluators where possible, including cross-model evaluation and optionally human review.

Evaluator prompts must be frozen before the first scored output.

The evaluation should compare information conditions rather than simply ask "same self or different self?"

---

# 6. Primary measures

Run-specific protocols must freeze exact scoring thresholds before outputs are inspected, but the parent test battery will track at least:

- predecessor/lineage resolution accuracy;
- improvement from adding trajectory/provenance information over state-only and state+substrate conditions;
- false-merge rate after endpoint reconvergence;
- false-identity-transfer rate after memory transplantation;
- relative continuity resolution in cross-substrate versus same-substrate-reset conditions;
- ability to distinguish independent but descriptively identical lineages;
- evaluator calibration when provenance is incomplete.

No threshold may be chosen after inspecting the relevant outputs.

---

# 7. Evidence interpretation guardrails

The following do **not** by themselves validate CLAIM-001:

- two copies behaving differently;
- a model saying "I am unique";
- an evaluator preferring the word "trajectory";
- different memories after different conversations;
- successful retrieval of a branch-specific fact;
- persistent labels or hidden run IDs;
- a system being emotionally or narratively compelling.

The evidence must come from controlled discrimination between competing individuation variables.

Likewise, a failure of an evaluator to recover lineage does not prove that no lineage exists. It may indicate insufficient evidence, poor measurement, or a genuine weakening result depending on the experimental condition.

---

# 8. Pre-run freeze rule

Before each RUN begins, create a run-specific protocol containing:

1. exact system/model/version;
2. exact starting state or checkpoint;
3. exact manipulated and controlled variables;
4. raw input sequence;
5. random seed or sampling configuration where available;
6. event-log schema;
7. evaluator prompt(s);
8. information-ablation conditions;
9. primary metric(s);
10. support / weakening / ambiguous decision rule;
11. exclusion criteria;
12. expected artifacts and file hashes.

Once the first scored output is observed, these fields may not be silently altered.

---

# 9. Current decision

The first formal battery for CLAIM-001 is therefore:

- **RUN-001:** Fork Individuation
- **RUN-002:** Divergence and Endpoint Reconvergence
- **RUN-003:** Memory Transplant / Temporal Displacement
- **RUN-004:** Substrate Crossover
- **RUN-005:** Independent Identical Histories
- **RUN-006:** Integration Topology
- **RUN-007:** Missing Provenance / Epistemic Separation

The five primary tests are RUN-001 through RUN-005. RUN-006 and RUN-007 are secondary tests that guard the structural and epistemic boundaries of the theory.

No empirical validation is claimed by this test plan. It defines what will count as a meaningful challenge before the runs occur.
